Chapter 1 • Foundations

Git vs. GitHub & The Essential Dictionary

First, people often use the words Git and GitHub as if they are the same thing. Here is the simple difference:

⚙️ Git (The Time-Machine Engine)

A tracking tool that records every file change over time so you can always rewind to an older version if something breaks.

🌐 GitHub (The Shared Cloud Website)

The website (github.com) where teams store their Git projects online, review each other's drafts, and collaborate safely.

The 8 Words You Will See Every Day

1. Repository (Repo) 📁 Project Folder

The master folder on GitHub that holds all files, manuals, scripts, and version history for one project.

2. Main Branch (main) 🏆 The Official Live Copy

The trusted, published version of the project. Everyone relies on main being clean and working.

3. Branch 📝 Safe Photocopy / Save Slot

Your private working draft inside a repo where you edit files without risking the official main copy.

4. Commit 💾 Save Checkpoint + Note

Saving changes on your branch with a short message explaining what changed and why.

5. Pull Request (PR) 👀 Approval Request

Asking your team to inspect your branch changes before combining them into the official main branch.

6. Merge 🚀 Publish to Official

Combining your approved branch into main so your updates become part of the official project.

7. Fork 🍴 Personal Copy of Another Repo

Copying someone else's entire repository into your own GitHub account so you can experiment freely.

8. Clone 💻 Download to Your PC

Downloading a cloud repository onto your computer so you can edit files offline.

Chapter 3 • Interactive Daily Checklist

The 5-Step Daily Routine

Use this interactive checklist every time you need to add or edit a file on GitHub. Click each step as you complete it!

  1. Step 1: Create a Fresh Branch from main

    Never reuse old branches. Create a new branch named after today's task.

    GitHub UI: Click "main" dropdown (top-left) → Type branch name → Click "Create branch"

  2. Step 2: Edit or Upload Your File

    Verify the branch button says your new branch name, then make your edits.

    GitHub UI: Open file → Click Pencil icon (✏️ Edit) OR click "Add file"

  3. Step 3: Commit (Save) with a Clear Message

    Write a 1-sentence summary so anyone looking at the history knows what changed.

    GitHub UI: Green "Commit changes..." button → Enter message → Commit to your branch

  4. Step 4: Open a Pull Request (PR)

    Propose merging your branch into main so a teammate can review or verify it.

    GitHub UI: Click yellow banner "Compare & pull request" → "Create pull request"

  5. Step 5: Merge & Delete the Temporary Branch

    Combine your changes into main, then delete the branch to keep the repo tidy.

    GitHub UI: Click "Merge pull request" → "Confirm merge" → "Delete branch"

Action Where Does It Live? When Do You Use It? Simple Analogy
🔀 Branch Inside the same repository on GitHub You are part of the team and have permission to edit the repo. Making a new tab inside your team's shared Google Sheet.

Version Management, History & Rollbacks

GitHub is a complete Version Management System. Every time someone merges or commits a change, GitHub records:

  • Who made the change (Author)
  • When it happened (Timestamp)
  • A Unique Fingerprint (Commit SHA) — e.g., 94b808e, which acts like a receipt number
  • The Exact Diff — which lines were removed (red -) and added (green +)

Understanding Version Numbers (Semantic Versioning)

When teams publish official milestones on GitHub (under Releases / Tags), they use 3 numbers: vMAJOR.MINOR.PATCH (for example, v2.4.1):

MAJOR (2.x.x)

Big overhaul or changes that aren't backward-compatible.

MINOR (x.4.x)

Added a helpful new feature or chapter without breaking anything.

PATCH (x.x.1)

Small bug fix, typo correction, or security patch.

Chapter 6 • Interactive Lab #4

What Is a Merge Conflict? (+ Interactive Resolver)

New users often panic when they see the words "This branch has conflicts that must be resolved." Don't worry—nothing is broken!

A merge conflict only happens when two people edit the exact same line of the exact same file at the same time. GitHub pauses and asks you which line to keep.

Chapter 7 • Collaboration & Security

Issues, Security Rules & .gitignore

1. GitHub Issues (Your Built-In Ticketing System)

The Issues tab at the top of a GitHub repo works just like an IT helpdesk ticket board:

  • Use Issues to report a broken script, request new documentation, or track a to-do list.
  • Magic Trick: Every Issue gets a number (like #4). If you write Fixes #4 in your Pull Request description, GitHub will automatically close Issue #4 the moment your PR is merged!

2. Security Golden Rule & What .gitignore Does

🔒 Critical IT Security Rule:
NEVER upload passwords, Personal Access Tokens, API keys, private SSH keys, or employee personal data to a GitHub repository! Even if you delete a file later, it remains visible inside the Git commit history.

To prevent accidental uploads of sensitive or junk files, professionals place a special file named .gitignore in their repository. Any file name or folder listed inside .gitignore (like .env, passwords.txt, or *.log) is automatically ignored by Git.

🆘 Searchable "I'm Confused!" Rescue FAQ

How do I know which branch I am currently looking at?

Look at the top-left corner above the file list on GitHub. The button with the branch icon (🔀) displays the name of the active branch (such as main or update-guide).

I saved (committed) changes, why don't I see them on the main page?

Because they are safely isolated inside your branch! Complete Step 4 (Pull Request) and Step 5 (Merge) to bring them into main, or switch the branch dropdown at the top-left to view your branch.

I messed up my branch completely! Did I break the live project?

No! As long as you worked on a branch and not main, the live project is 100% safe. Open Your Branches, click the trash can icon (🗑️) next to your broken branch, and create a fresh branch from main.

Someone already merged changes into main after I started my branch. How do I catch up?

On your Pull Request page or branch view, GitHub shows an "Update branch" or "Sync fork" button. Click it and GitHub will bring the latest updates from main into your branch.

Should I delete my branch after merging a Pull Request?

Yes! Once merged, your commits are permanently part of main. Deleting the merged branch keeps your repository clean and prevents anyone from accidentally editing an old branch later.
