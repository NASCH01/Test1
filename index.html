Chapter 1

The 6 Words You Need to Know

GitHub uses special words for very simple everyday things. Here is your cheat-sheet translator:

1. Repository (Repo) Analogy: A Project Folder

The main folder on GitHub that holds all the files, documentation, and history for one project.

2. Main Branch (main) Analogy: The Official Master Copy

The live, working version of the project. Everyone trusts that files in main are tested and approved.

3. Branch Analogy: A Safe Photocopy / Save Slot

Your personal workspace copy of the project where you can edit files without breaking the official main copy.

4. Commit Analogy: Clicking "Save" + a Note

Saving your changes on your branch along with a short message explaining what you changed (e.g., "Updated printer setup IP").

5. Pull Request (PR) Analogy: "Please Review My Draft"

A request asking your team to look at your branch changes before combining them into the official main branch.

6. Merge Analogy: Publishing Your Changes

Combining your approved branch changes into the official main branch so everyone gets the update.

Chapter 2

How Branches Work (And Why We Use Them)

Imagine your IT team shares an important instruction manual. If three people edit the live manual at the exact same time, someone's work gets overwritten or broken.

⚠️ The Golden Rule of GitHub:
Never make changes directly inside the main branch. Always create your own branch first!

When you create a branch, GitHub makes an instant parallel copy for you:

main (Official): ───●──────────●────────────────────●─── (Updated & Safe!) \ / your-branch (Draft): └──● (Edit 1) ──● (Edit 2) ─┘ ↑ ↑ 1. Create Branch 4. Merge via PR
  • You can't break anything: Even if you delete half the files on your-branch, the main branch is 100% unharmed.
  • Easy undo: If you realize your idea isn't needed anymore, you just delete your branch and walk away.
Chapter 3

The 5-Step Daily Routine

Every time you are asked to update a file, add documentation, or fix a script on GitHub, follow these exact 5 steps:

  1. 1

    Create Your Branch

    Start from main and create a fresh branch named after your task.

    Where to click: Branch dropdown (top-left, says "main") → Type new name → Click "Create branch"
  2. 2

    Make Your Changes

    Open the file you need to update (or upload/create a new file) while making sure you are inside your new branch.

    Where to click: Click the Pencil icon (✏️ Edit this file) or "Add file"
  3. 3

    Commit (Save) Your Changes

    Save your edit and write a short, clear sentence explaining what you did.

    Where to click: Green "Commit changes..." button (top-right) → Add message → Commit to your branch
  4. 4

    Open a Pull Request (PR)

    Tell your team your branch is ready to be checked and combined into main.

    Where to click: Yellow banner "Compare & pull request" → Click "Create pull request"
  5. 5

    Merge & Clean Up

    Once approved (or if you are working solo and verified everything looks right), merge the PR and delete the old temporary branch.

    Where to click: Green "Merge pull request" button → "Confirm merge" → "Delete branch"
Chapter 4

Branch Naming & Best Habits

Keep branch names short, lowercase, and separated by hyphens (-) so anyone on the IT team knows what you are working on at a glance.

✅ Good Branch Names

update-wifi-guide
fix-login-script
add-onboarding-checklist

❌ Avoid These Names

test123 (Too vague)
nicolas-branch (Doesn't say what task)
patch-final-v2-new (Confusing)

💡 Pro Habit — One Task Per Branch:
If you need to update the Wi-Fi guide and fix a backup script, make two separate branches. Small branches are much easier to review and undo!
Chapter 5

"I'm Confused!" — Quick Rescue FAQ

Click on any question below when you aren't sure what's happening:

How do I know which branch I am currently looking at?

Look at the top-left corner of the file list on GitHub. There is a button with a branch icon (🔀). Whatever word is written on that button (for example, main or update-guide) is the branch you are currently viewing.

I saved (committed) changes, why don't I see them on the main page?

Because you saved them safely inside your branch! They won't appear on main until you complete Step 4 (Pull Request) and Step 5 (Merge). Switch the branch dropdown at the top-left to your branch name to see your files.

I messed up my branch completely! Did I break the project?

No! As long as you were working on a branch and not main, the official project is completely untouched. You can simply go to Your Branches, click the trash can icon next to your broken branch, and start a fresh one from main.

What does "Merge Conflict" mean?

It simply means two people edited the exact same lines of the exact same file at the same time, and GitHub is asking a human: "Which version of this paragraph would you like to keep?" Nothing is broken—you just pick the right lines and click Commit.

Should I delete my branch after merging?

Yes! Once your changes are merged into main, your changes are permanently saved in main. Deleting the old branch just keeps the branch list tidy (like throwing away a sticky note after finishing the chore).
